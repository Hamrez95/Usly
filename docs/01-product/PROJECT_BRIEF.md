# قرارداد محصول Usly — مسیر Closed Beta

## کاربر و مسئله

زوج‌های شاغل ۲۵ تا ۳۸ سال که برای تبدیل نیت خوب به یک برنامه مشترک واقعی،
با کمبود زمان، انرژی متغیر و تصمیم‌گیری تکراری روبه‌رو هستند.

## خروجی قابل اندازه‌گیری

هر دو نفر در کمتر از پنج دقیقه پاسخ خصوصی بدهند، یک پیشنهاد مشترک انتخاب کنند
و در ادامه آن را زمان‌بندی و انجام‌شده ثبت کنند. معیار شمالی محصول، «زوج‌های
فعال هفتگی که یک تجربه مشترک را کامل کرده‌اند» است.

## مسیر اصلی

ورود مستقل → اتصال رضایت‌محور زوج → پاسخ خصوصی → زمینه خنثی → سه پیشنهاد →
رأی خصوصی → حل اختلاف بدون افشای رأی → انتخاب → زمان‌بندی → انجام → بازخورد.

## پلتفرم و محدوده آلفا

- Android اولویت اول؛ Flutter یک کدبیس.
- فارسی RTL از ابتدا؛ معماری انگلیسی LTR و dark mode حفظ می‌شود.
- Supabase برای Auth، PostgreSQL، RLS و وضعیت مشترک.
- پیشنهادها deterministic و از محتوای curated؛ بدون مشاور AI.

## خارج از محدوده

درمان، امتیاز رابطه، چت، شبکه اجتماعی، مکان دقیق، بانک، تبلیغ مبتنی بر داده
حساس، فروشگاه عمومی و پرداخت.

## الزام‌های غیرعملکردی

- هیچ پاسخ خامی برای شریک، log، analytics یا notification قابل مشاهده نیست.
- مسیر اصلی در قطع/وصل شبکه idempotent و قابل بازیابی باشد.
- تم روشن/تاریک، reduced motion، لمس حداقل ۴۸dp و text scaling پشتیبانی شود.
- انتشار فقط با صفر P0/P1، امتیاز Foundry حداقل ۹۰ و APK smoke-tested.

## کارهای وابسته به حمیدرضا که فعلاً مانع توسعه نیستند

- تنظیم SMTP اختصاصی و Redirect URLهای Auth قبل از دعوت کاربر خارج از تیم.
- تست نصب و مسیر دوگوشی روی دو دستگاه واقعی بعد از تحویل APK کاندید.
- نگهداری امن keystore انتشار Android پیش از نسخه عمومی یا Store.

این موارد تا زمان رسیدن کاندید نسخه به گیت مربوطه عقب انداخته می‌شوند.
